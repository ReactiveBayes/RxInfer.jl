Early stopping

RxInfer supports early stopping as an opt-in callback via StopEarlyIterationStrategy. For a general overview of the callbacks system, see the Callbacks section.

Constructors

  • StopEarlyIterationStrategy(rtol; window = 2): sets atol = 0.0, uses the given relative tolerance.
  • StopEarlyIterationStrategy(atol, rtol; window = 2): sets both absolute and relative tolerances.
  • Both constructors use start_fe_value = Inf for the initial comparison value.
RxInfer.StopEarlyIterationStrategy — Type
StopEarlyIterationStrategy

Early-stopping criterion based on a window of consecutive Bethe free energy (FE) values. window = 2 preserves the consecutive-value isapprox criterion. Larger windows require maximum(values) - minimum(values) <= max(atol, rtol * maximum(abs, values)). History resets at iteration one of each solve or streaming observation event.

Fields

  • atol::Float64: Absolute tolerance.
  • rtol::Float64: Relative tolerance.
  • start_fe_value::Float64: Initial FE reference used before the first iteration.
  • fe_values::Vector{Float64}: History of observed FE values (most recent is last).
  • window::Int: Number of consecutive FE values required (at least two).

Constructors

  • StopEarlyIterationStrategy(rtol): uses atol = 0.0, custom rtol.
  • StopEarlyIterationStrategy(atol, rtol): custom absolute and relative tolerances.

Both constructors use start_fe_value = Inf by default to avoid immediate stopping on the first iteration.

Early stopping mechanism

The BeforeIterationEvent and AfterIterationEvent carry a mutable stop_iteration::Bool field (default false). Any callback can set event.stop_iteration = true to signal the inference engine to stop iterating. The StopEarlyIterationStrategy uses this mechanism internally — when the free energy has converged, it sets event.stop_iteration = true.

Check out more about callbacks for static inference here.

Note that in this case we still have to specify the iterations, which in the case of early stopping specifies maximum number of iterations.

The default window = 2 compares consecutive values with isapprox, preserving the previous behavior. For example, window = 4 requires four finite BFE values whose full range satisfies maximum(values) - minimum(values) <= max(atol, rtol * maximum(abs, values)). This prevents several individually small changes from accumulating into a larger drift within the window. Four values span three iteration-to-iteration changes.

The same before_iteration and after_iteration callbacks are supported in streaming inference. A stop flag ends only the current observation event's solve; posterior publication, history saving, and processing of future events continue. The strategy resets its BFE history at iteration one of every new solve/event, so values from different observations are never compared. Streaming BFE histories contain only executed iterations; the per-iteration average includes only events that reached that iteration. A stop before the first iteration produces no tick or history entry for that observation event.

Use a separate strategy instance for each concurrently running inference engine. BFE stability is a stopping heuristic, not a guarantee of posterior accuracy.

Batch example: early stopping and convergence windows

Consider five noisy sensor readings with an unknown mean and precision. First, we demonstrate how an early-stopping callback saves iterations compared with a fixed budget of 50. We also compare the default window = 2 with window = 4, using the same BFE tolerance, to see how the window affects when inference stops and how closely the estimated mean agrees with the full run.

using RxInfer

@model function iid_normal(y, n)
    m ~ Normal(mean = 0.0, variance = 1.0)
    tau ~ Gamma(shape = 1.0, rate = 1.0)
    for i in 1:n
        y[i] ~ Normal(mean = m, precision = tau)
    end
end

data = (y = [3.2, 3.7, 4.0, 4.4, 4.7],)
max_iterations = 50
initialization = @initialization begin
    q(m) = NormalMeanVariance(0.0, 1.0)
    q(tau) = GammaShapeRate(1.0, 1.0)
end

function fit_batch(window)
    return infer(
        model = iid_normal(n = length(data.y)),
        data = data,
        constraints = MeanField(),
        initialization = initialization,
        free_energy = true, # The stopping callback monitors BFE.
        iterations = max_iterations, # With early stopping, this is an upper limit.
        returnvars = (m = KeepLast(),),
        callbacks = isnothing(window) ? nothing : (
            after_iteration = StopEarlyIterationStrategy(0.0, 0.01; window),
        ),
    )
end

# No callback: execute the full iteration budget as a reference.
reference = fit_batch(nothing)
# Early stopping: compare consecutive BFE values (2) with a four-value window (4).
results = [fit_batch(window) for window in (2, 4)]
mean_errors = [abs(mean(r.posteriors[:m]) - mean(reference.posteriors[:m])) for r in results]
[(; window, iterations = length(r.free_energy),
    saved_iterations = length(reference.free_energy) - length(r.free_energy),
    mean_error = error)
 for (window, r, error) in zip((2, 4), results, mean_errors)]
2-element Vector{@NamedTuple{window::Int64, iterations::Int64, saved_iterations::Int64, mean_error::Float64}}:
 (window = 2, iterations = 8, saved_iterations = 42, mean_error = 0.33889370094430626)
 (window = 4, iterations = 12, saved_iterations = 38, mean_error = 0.054469199232909826)

Both callbacks stop before the 50-iteration limit. saved_iterations counts the rounds of message updates avoided, while mean_error measures the difference from the full run's estimated mean.

With window = 2, two adjacent BFE values pass the 1% tolerance while the BFE is still drifting across the last four iterations. window = 4 waits for a flatter plateau and gives a mean closer to the reference, while still saving iterations. A larger window remains a heuristic, so check the posterior quantities that matter for your application.

Streaming example: stopping each observation separately

Suppose a sensor sends batches of noisy readings, and we estimate the mean and precision of each batch using the model and initialization above. Streaming early stopping avoids spending the full 50 iterations on every batch. We use the default window = 2 here. The model's explicit size n lets streaming inference construct the graph before readings arrive.

batches = [offset .+ [-0.8, -0.3, 0.0, 0.4, 0.7] for offset in (0.0, 0.0, 2.0)]
engine = infer(
    model = iid_normal(n = 5),
    data = (y = batches,),
    autoupdates = RxInfer.EmptyAutoUpdateSpecification,
    constraints = MeanField(),
    initialization = initialization,
    iterations = max_iterations,
    free_energy = true,
    callbacks = (after_iteration = StopEarlyIterationStrategy(1e-10, 1e-8),),
    keephistory = length(batches),
    historyvars = (m = KeepEach(),),
)

iterations_per_batch = length.(engine.history[:m])
(; iterations_per_batch,
   saved_iterations = length(batches) * max_iterations - sum(iterations_per_batch))
(iterations_per_batch = [6, 2, 9], saved_iterations = 133)

The empty auto-update specification selects streaming inference without carrying posterior parameters into the next batch's prior. The second batch repeats the first, but still needs its own two-value comparison: the strategy resets its BFE history for each batch. Stopping one batch also leaves the engine ready to process the third batch, whose mean has shifted. KeepEach() records only the iterations actually executed; without the stopping callback, each batch would use all 50.
